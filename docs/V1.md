# Version 1

One definition, one list, one order. `ROADMAP.md` records what happened;
this page says what is left and when it is finished. If a "what next"
answer disagrees with this page, this page is wrong and needs editing,
not the answer.

## What version 1 is

**One Discord server, protected end to end.**

The loop from the product statement, working for real on somebody's
server: messages arrive, Guardian scores them for the six-stage ladder,
anything that looks like the pattern lands in a review queue, a person
confirms it, and a confirmed case becomes a CyberTipline report with a
tamper-evident evidence bundle and a one-year preservation hold.

That is a complete product. It is the first of the four surfaces, and
DESIGN.md section 11 puts it first for the same reason: it is the only
one that needs nobody's signature to start.

## What version 1 is not, and why

| Excluded | Why |
|---|---|
| Investigator triage (phase 4) | Cannot start without a signed LE or NGO partner naming a custodian and scope. No amount of code moves it. |
| Parent app (phase 5) | Counsel has to clear the consent posture first, and the vendor exposure is 18 USC 2512 and FTC stalkerware precedent. DESIGN.md section 11 puts it last. |
| Stage classifier, learned fusion | Both need PANC or PJZC, which are decoy transcripts Guardian does not hold. The rule kernel is the product until then, and the model card says so. |

| Platform SDK go-live | Built and tested. It ships when a customer exists; nothing is left to write. |

The platform SDK is the one row where "not in v1" means "waiting for a
buyer" rather than "waiting for work".

## The four gates

Version 1 is done when all four pass.

| Gate | Test |
|---|---|
| **G1. It runs** | The bot is in a real guild, scoring real traffic, and the mod channel has received an alert nobody wrote by hand. |
| **G2. A person can finish a case** | A reviewer proposes T3 in the console and a second reviewer upholds it in the console. No script, no test harness. |
| **G3. The report is real** | A confirmed T3 produces a CyberTipline submission NCMEC accepts, or a drafted bundle the operator files, with the one-year hold set. |
| **G4. Nothing on screen breaks a rule** | Every string passes the accusation guard, the byte guard holds, retention runs, and the audit chain verifies offline. |

G2 and G4 pass. G1 and G3 do not, and both are waiting on somebody
outside this repository.

## The work, in order

### 1. The T3 path in the console

**Done.**

`recordDecision` accepted a `Concurrence` and refused T3 without one, and
nothing in the UI ever supplied one: `scripts/integration/e2e.test.ts`
was the only thing in the repository that had ever produced a T3. A
proposal left the pair at T2 with `resolvedAt` unwritten, so it returned
to the queue looking exactly like every other T2, and there was no
control to uphold it, overturn it, or withdraw it. The product
statement's fourth sentence, "a person confirms it", was not reachable by
a person.

**What the build turned up on the way.** `Review` had no column for the
state of a decision and none for the proposal a concurrence answers, so
an open proposal was not answerable from a query at all; both are columns
now, and the state column is also the lock, because closing the proposal
is an `updateMany` with `state: "proposed"` in the where clause and a
second answer matches no row.

And the read gate was satisfied by the wrong person. `Pair.humanViewedAt`
is set by whoever read first and records nobody, so the second reviewer
passed it on the proposer's read: they could have written T3 having
opened nothing. The check is now against that reviewer's own
`evidence.read` entries on the chain, which is the only place the reader
is named. That also meant `markExcerptsViewed` had to stop returning
early when every flag was already set, because a second reader wrote
nothing, returned nothing and appended nothing.

Ten unit tests, eight component tests, and the live-Postgres e2e now
covers the proposal being closed by the answer that names it.

### 2b. Guardian sees almost nothing in an open channel

Found on the first real message. `targetOf` in `apps/discord-bot/src/mapping.ts`
returns a target only when a message is a reply, or carries exactly one
`@mention`. Everything else maps to `targetUid: null`, the kernel returns null
for it, and nothing is scored, stored or paired.

In a 40-person game community's `#general`, two people talk to each other for
twenty messages without replying or @-mentioning once. That is the traffic this
product exists to read, and today it is invisible. The nine-message ladder that
proved the pipeline worked because the driver set a mention on every line.

This is the largest detection gap in the shipping surface and it is not on the
old open list, which recorded only that open-channel messages have no events
row. Adjacency is the fix: two accounts posting in the same channel inside a
short window are a candidate pair, scored with lower confidence than a reply,
and the pair term already carries the machinery to weigh it. It needs a design
decision about false pairs in a busy channel before it is written.

### 3. Close the open sweep findings

**All four are closed.**

| | Finding | Note |
|---|---|---|
| ~~**S-2**~~ | Actor band provenance and confidence were never written. | **done.** `ActorState` carries both, the kernel applies the event's reading on both sides of the pair, and `resolveBandReading` orders the seven sources so a weaker one cannot overwrite a stronger one and the band moves with its provenance. The pair's cached bands take the same resolved values, so the score and the case page cannot disagree about which band is in force. |
| ~~**S-9**~~ | `modelTier` meant two things. | **done.** The column that held the tier at the decision is `priorTier`, which is what undo restores and what the chain records. `Pair.modelTier` and `Review.modelTier` are the kernel's own answer, written only by `recordTier`, so the T2 predictive-value denominator stops counting a reviewer's own T2 as a model prediction. Nullable with no backfill: for a row written before this, the model's tier is not knowable, and a guess in a calibration denominator is worse than an absence the metric excludes. |
| ~~**S-6**~~ | A scoped audit export leaked a per-version census of the withheld rows. | **done.** The census runs after the scoping filter. The withheld count stays, because that is the number that tells a redacted export from a short one, and a count of rows a reader cannot see says nothing about whose they are. |
| ~~**S-4**~~ | Raw message text sat in Redis for as long as the stream was retained. | **done. Rule 7 covers the queue.** A queued event is raw text Guardian is holding, and which store it sits in does not change what it is, so the sweep gained a `streams` step at the same 24 hour cutoff rather than the rule gaining an exception. The MAXLEN on append was never a retention control: Redis keeps an entry after XACK, so a quiet partition held every message it had ever carried. |
